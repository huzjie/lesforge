# 设计决策（为什么这样做）

1. **零依赖**：目标场景是「读代码学习 + 快速跑通」，不因装 numpy/pytorch 卡住。
   张量用 Python 列表，确定性随机用 `md5 -> random.Random`。

2. **专家是调度的最小单位**：卸载、预取、量化、驱逐都以「单个专家的权重矩阵」
   为粒度，与真实 MoE 的专家粒度一致。

3. **能力 = 标量 skill，且训练信号单调趋 1**：这是本仓库系列反复验证过的 mock
   套路——打分必须是 `boost=(skill-0.5)*2`，skill=0.5 时 boost 恰为 0（随机基线），
   训练用 `skill += lr*(1-skill)` 单调爬升，避免「对+1 错-1」导致的负漂移。

4. **路由用均值池化的隐藏态**：调度层面每层只关心「激活哪几个专家」，用序列均值
   代表，既保持确定性，又让「下一层真实路由」可被前瞻预测器直接对照。

5. **冷启动不算调度失误**：第 0 层的专家加载是不可避免的初始 I/O，命中率只统计
   之后各层由预取带来的命中。
